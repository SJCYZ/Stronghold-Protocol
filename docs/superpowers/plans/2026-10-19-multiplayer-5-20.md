# 5–20 人多人能力移植实施计划

> **给执行代理的要求：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 子技能，按任务逐项实施；使用复选框跟踪。各任务完成后独立验证并提交。

**目标：** 在当前 Stronghold-Protocol 中支持最多 20 名参战者，并在实际参战人数超过 4 时启用独立库存、逐小队机变与全房间两轮联防等多人规则。

**架构：** 保留 `MAX_SEATS = 4` 作为快速匹配组队上限，新增合作房间/对局的 20 人边界。Match 开局冻结参战者、变体标志及供逐小队机变使用的开局小队映射；服务端 Match Worker、增量状态、Redis 检查点和现有模拟协议继续承担对局运行。房间容量、对局库存、逐小队机变、全房间两轮联防和战斗扩容按任务分段，共用冻结参战者模型。

**技术栈：** Node.js ES modules、WebSocket 协议、Redis 持久化 Worker、浏览器端 Preact/HTM、Vite、`node:test`。

**设计规格：** [`docs/superpowers/specs/2026-10-19-multiplayer-5-20-design.md`](../specs/2026-10-19-multiplayer-5-20-design.md)

## 全局约束

- 合作房间容量为 4–20，默认 4；快速匹配仍为四人；AI 计入参战人数，观战者不计。
- 仅 `participants > 4` 开启变体；Match 创建后冻结 `participants`、`variant` 和供机变使用的 `squadId → playerIds`，队伍每四名开局参战者按座位顺序固定分组。联防从全房间参战者结果中随机选人，不按固定小队拆分。
- 四人及以下沿用当前池、机变视图/选取顺序、计时及效果范围。
- 多人变体每队独立六张机变卡、各自进度/卡槽占用/时限；卡面只发给本队成员，团队卡只作用于本队。
- 保留当前共享装备库存、`itemPoolCopies` 来源账本、被动赠送和控制台装备规则；干员库存改为每玩家隔离。
- Match 继续使用当前完整 Match Worker 池；保留增量状态基线、断线全量重同步及 Redis 检查点 generation/recovery 规则。
- 五人以上联防第一轮汇总全房间计数漏怪；每轮从全房间完美通过者中随机、轮内无放回抽取最多两人，总共最多两轮。第二轮只防守第一轮残敌，允许再次选中同一人；每轮使用随游戏回合递增且封顶 150 秒的真实时限。≤4 人保持现有单轮行为。
- 联防沿用当前回合地图、地形、阻隔物、设备和 `stageId`；逃逸模板只提供漏怪重入批次/路线，最终仍按原来源玩家计算 LP。
- 首领血量按开战时存活参战人数扩展；独立玩家战场仍保持 600 个存活敌人上限，共享战场按该场参战人数线性扩展。
- 全服 `SP_MAX_CONNECTIONS`（默认 2000）、未认证连接限制、每网络连接限制不随房间容量变化。
- 不在本计划中部署、重启生产服务器或更改 Redis/OpenResty 运行配置。

## 审查重点

1. 四人及以下的协议、随机流、共享库存和公共机变卡面必须保持原样；由任务 4–7 的旧路径回归覆盖。
2. 容量 20 不得扩大快速匹配；房间容量不得覆盖实际开局人数闸门；由任务 1–3 的房间/匹配测试覆盖。
3. 多队机变卡面、卡槽索引、团队效果及超时必须按认证玩家所属小队隔离；由任务 6–7 的跨队隐私和串选测试覆盖。
4. Redis 恢复并行机变不得重抽卡、重复应用已选效果或丢失某队时钟；由任务 6 的快照测试覆盖。
5. 五人以上联防每轮从全房间完美通过者中随机抽最多两人，最多两轮且第二轮只守第一轮残敌；每轮真实时限不超过 150 秒，地图、援助者 HP/SP 携带、漏怪归责和敌人/结果预算适用于最多 20 人；由任务 8–9 的轮次、恢复、地图、结算及协议测试覆盖。

## 文件与接口分工

- `shared/constants.js` / `shared/protocol.js`：房间与参战人数边界、协议版本、结果列表人数校验。
- `server/lobby.js` / `server/publicApi.js`：房间容量、入座/开局/快速匹配边界和公开房间列表。
- `server/persist.js` / `server/workers/persistenceClient.js` / `server/match/snapshot.js`：旧记录默认值、新容量/小队/多池/多队机变的安全恢复。
- `server/match/Match.js` / `server/match/match/views.js` / `server/match/player/views.js`：固定 Match 参与者与小队、公开/私有状态。
- `server/match/pool.js` / `server/match/player/*.js` / `server/match/invariants.js` / `server/match/bot.js`：按玩家路由干员库存；`itemPool` 保持独立。
- `server/match/match/spDraft.js` / `server/match/choices.js` / `server/match/audit.js`：每小队卡池、独立选取/时钟、团队卡作用范围与审计。
- `public/js/ui/gameLogic/draft.js` / `phases.js` / `public/js/ui/choiceOverlay.js` / `public/js/screens/game.js`：兼容旧机变结构及新增小队私有卡池展示。
- `server/match/unite.js` / `server/match/match/unitePhase.js` / `server/match/waves.js` / `server/match/snapshot.js`：全房间随机援助者、两轮联防与恢复，沿用本回合战场。
- `server/match/gamedata.js` / `server/sim/constants.js` / `server/sim/battle/spawns.js` / `shared/protocol.js`：Boss 血池、按战场人数缩放的活敌上限与结果校验预算。
- `public/js/screens/lobby.js` / `room.js` / `public/css/screens/room.css` / 中文文案：建房容量、房主改容量及 20 席滚动布局。

## 已确认的计划约定

1. 变体每玩家的普通干员池容量沿用当前同盟 `GameData.poolCopies()` 数值，仅把库存所有权分给玩家；装备与 DIY 库存完全沿用旧账本。
2. 五人以上的联防不按固定小队拆场：第一轮防御全房间所有玩家的计数漏怪，每轮从本回合完美通过者全集随机、无放回抽取最多两人，最多两轮，第二轮只防御第一轮残敌且允许重抽到同一人。
3. 每轮联防真实时限沿用按回合递增的 `combatTimeLimitReal(round)` 并封顶 150 秒，再按 `combatTimeScale` 转模拟时间；候选、每轮抽选和进度必须在检查点保存，恢复不得重抽。
4. 共享战场活敌上限使用 `600 × 该 BattleSpec 的实际参战玩家数`；单人/正常独立战场保持 600，最多 20 人时场级上限为 12,000。

计划把这项移植作为一个版本内的串行任务组，因为容量、固定小队、Match 状态和检查点彼此依赖；每个任务都能单独测试、审查和提交。生产部署与重启另行准备。
