# 游戏登录鉴权与单局访客分享设计

日期：2026-10-21
状态：已通过会话设计确认，待用户审阅本文

## 目标

为 Stronghold-Protocol 增加基于 Web Gerber Share Station（WGS）账号的登录鉴权。未登录访客只能凭登录玩家分享的单局码进入指定房间和本局；访客可在本局中断线重连，但本局结束后不能继续加入或创建其他对局。

## 已确认规则

- Stronghold 复用 WGS 现有登录页和账号，不提供注册，也不接收或保存账号密码。
- 可登录账号必须有效、未封禁、邮箱已验证且已绑定 QQ。WGS 全站 SMTP 初始化状态不影响游戏登录。
- 游戏认证来自服务端完成的 WGS SSO 交换，不信任客户端提供的账号 ID、昵称或旧匿名令牌。
- 登录账号按现有 Stronghold 房间和匹配能力游玩；访客只通过单局分享码进入其授权房间。
- 一个分享码可在开局前由多名访客使用；对局开始后停止首次兑换，仅允许已加入访客用各自的会话凭证重连。
- 对局结束、对局取消或房间关闭后，分享码及访客会话均失效。访客不能创建房间、发起匹配、进入其他房间或旁观其他对局。
- 现有四字符房间码仅作为房间定位符，不授予访客权限。
- 升级前保存的匿名会话不自动迁移为账号或访客。它们不能重连、加入或创建对局；玩家需重新登录或使用新分享码。升级后旧匿名对局可能无法恢复。

## 身份与授权流程

### WGS SSO

1. Stronghold 开始登录时生成随机 state 和 PKCE verifier/challenge，并保存短时登录事务。
2. 浏览器导航至 WGS 的 SSO 授权入口。WGS 只接受预先登记的 Stronghold client 和精确回调地址；不接受任意 redirect URI。
3. WGS 复用现有登录页及其验证流程。授权和兑换时都检查账号有效、未封禁、邮箱已验证、QQ 已绑定；SMTP 初始化标志不作为 SSO 条件。
4. WGS 生成至少 128 位随机授权码。Redis 中只保存授权码摘要，TTL 为 60 秒；记录绑定 client、回调地址、PKCE challenge、WGS 会话和账号 auth_version。兑换时原子地将授权码标记为已使用。
5. 浏览器回调 Stronghold，Stronghold 核对 state 后，由 Stronghold 后端使用 client 凭据和 PKCE verifier 向 WGS 兑换授权码。client secret 只保存在服务端配置。
6. 兑换结果包含 WGS subject、auth_version、过期时间及仅供服务端调用的 SSO 会话引用；该引用有效期不超过原 WGS 会话。Stronghold 将这些信息绑定至自己的 Session；WGS 会话引用不发送给浏览器。
7. Stronghold 在新 WebSocket 握手、账号会话重连及创建/加入新对局等权限边界，向 WGS 重新核验 SSO 会话引用和账号当前状态。WGS 停用、封禁账号或撤销原登录会话后，后续核验失败；已在进行中的 WebSocket 不强制中断，玩家可完成当前对局。
8. WGS 不可用时，新账号登录和需要重新核验的账号重连/新对局操作失败关闭。访客的本局重连不依赖 WGS。

### Stronghold 身份类型

服务端 Session 明确区分：

- 账号 Session：包含 WGS subject、auth_version、SSO 会话引用和本地断线重连令牌。
- 访客 Session：包含 invite ID、room ID、match generation 和独立本地重连令牌。
- 旧匿名 Session：缺少以上身份字段时视为未认证，不允许进入游戏。

玩家昵称继续使用 Stronghold 现有规则。昵称只用于显示，不作为认证凭据。

## 单局分享码流程

- 已认证账号玩家在所属房间中为下一局生成分享码。分享码是独立于四字符房间码的 128 位随机秘密，可复制分享码或通过邀请链接分享。
- 兑换请求使用 POST 传递分享秘密，不把秘密放在 URL 查询参数中；若使用邀请链接，分享秘密放在 URL fragment，由客户端读取后通过 POST 发送。服务端对兑换入口限速，只保存分享秘密的摘要及其 room、待开始 match generation 和过期状态。
- 同一码可在开局前创建多个独立访客 Session，受现有房间人数/席位限制。访客只能进入该码绑定的房间。
- 房间启动对局时，服务端将已加入访客 Session 绑定到本局唯一 generation，并关闭新兑换。已加入访客以各自的本地重连令牌恢复本局。
- 对局取消或替换、对局结束或房间关闭时，撤销分享码并删除/失效其访客 Session。房间之后开始的新局必须重新由登录玩家生成分享码。
- 访客不能仅凭四字符房间码、昵称或普通匿名 hello 建立身份；也不能用旧访客令牌访问别的房间或后续对局。

## Stronghold 服务端和客户端边界

服务端在 WebSocket hello、房间加入、观战、房间创建、匹配排队和对局启动等入口检查已验证的身份类型与资源范围。客户端隐藏控件仅改善交互，不构成安全边界。

标题页提供 WGS 登录入口和访客分享码入口，不提供注册。房间界面为登录账号提供生成/复制单局分享码的控件。客户端只持有 Stronghold 自身的重连令牌；不接触 WGS client secret、SSO 会话引用或账号授权码兑换凭据。

## 持久化与失效处理

- Stronghold Redis 快照持久化 Session 身份类型、账号或访客范围及有效期。WGS SSO 会话引用仅保存在服务端数据中。
- 邀请资料按 room ID 和 match generation 隔离；禁止旧 generation 清理或覆盖新局的数据。
- WGS 将授权码摘要/状态存于现有 Redis，按 TTL 回收；授权码不得复用。
- 旧快照中无身份类型的匿名 Session 默认拒绝，不根据昵称、token 或房间成员关系推测其账号身份。

## 验收行为

- 无 WGS 登录或有效访客授权的 hello、房间加入和匹配入口会被服务端拒绝。
- WGS 未验证邮箱、未绑定 QQ、已封禁、已停用或被删除的账号不能建立或恢复账号 Session；SMTP 初始化状态不影响符合账号条件的登录。
- 一次性授权码过期、重复兑换、错误 client、错误 callback、错误 state 或 PKCE 不匹配均失败。
- 单局码可由多名访客在开局前兑换；开局后不能首次兑换；本局访客可断线重连；本局结束后其会话不能加入后续对局。
- Redis 恢复保留账号/访客身份范围；旧匿名 Session 不被提升权限。

## 不在本次设计范围

不更改 Stronghold 游戏规则、现有账号注册流程、WGS SMTP 设置流程、管理员/工作室权限，不部署或修改生产环境，不添加与单局访问无关的社交、好友或跨局访客账号功能。
