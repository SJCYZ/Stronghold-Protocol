# 房主战斗速度滑条设计

- 状态：待用户审阅
- 日期：2026-10-20
- 范围：移除本机 `combat-speed` 插件包，改由当前房间房主在战斗中通过内置滑条设置服务器权威速度。
- 前序设计：保留 `2026-10-19-sdk-combat-speed-design.md` 中的服务器时钟、`b.speed` 同步与 SDK 接口；本设计更新速度控制入口、保留范围和最大值。

## 目标

1. 房主可在战斗中将速度设置为 `0.1` 至 `4.0`，步进 `0.1`；默认速度为 `2.0`。
2. 房主设定在当前 Match 的所有后续战斗阶段沿用。新房间或新 Match 回到 `2.0`；速度不写入浏览器偏好或全局设置。
3. 只有服务端能改变逻辑战斗速度。所有参战者和观战者沿用现有服务器时钟及 `b.speed` 更新，不在客户端自行改变模拟速率。
4. 本机可选插件中移除当前 `combat-speed` 包，保留通用 `sp.clock.onPhase` SDK 接口及其他插件，包括 `life-rescue`。

## 非目标

- 不改变战斗规则、战斗模拟器、暂停权限或对局默认速度。
- 不将速度设置加入房间大厅、跨房间偏好或下一场 Match。
- 不移除通用 `clock.speed` 插件权限或重写 SDK 时钟；SDK 与内置控制共用 `0.1`–`4.0` 的时钟校验范围。
- 不修改 `life-rescue` 或音频插件。

## 服务端行为

- 新增 C2S 意图 `g.speed { speed }`。协议验证速度为有限数值且处于 `0.1`–`4.0`；Match 再验证 0.1 步进。
- Match 仅接受当前 `hostId` 对应的真人且未离场玩家发出的请求，并且 Match 正在运行活动战斗阶段、未暂停或冻结。房主即使已淘汰但仍留在房间，也保留调速权；非房主、观战者、已离场玩家、准备阶段、结算阶段及暂停期间的请求均拒绝。
- 通过现有 `MatchCombatClock.setSpeed()` 应用速度。沿用变速前 flush runner/pacer、重新映射逻辑时间和截止时间、刷新字段计时并广播 `b.speed` 的现有流程。
- 获准调速时同步更新当前 Match 的默认战斗速度，使后续活动阶段沿用该值。安全阶段保存的现有 Match 检查点字段 `gameSpeed` 必须在恢复时同步恢复为跨阶段默认值；新建 Match 仍从生产默认 `2.0` 初始化。内部 `opts.combatSpeed` 测试/工具覆盖继续生效，且不放宽房主意图的 `0.1`–`4.0` 范围。
- 继续沿用现有安全检查点语义：不增加活动战斗中的即时持久化；如果进程恢复到较早的安全检查点，按该检查点恢复 Match 状态。

## 界面与同步

- 在现有战斗顶栏加入速度滑条，范围 `0.1`–`4.0`，步进 `0.1`，旁边显示当前倍速。
- 活动战斗中仅房主可操作；其他玩家看到服务器确认的当前倍速且不能操作。暂停或没有活动战斗时不允许提交速度。
- 拖动时展示本地选择值，交互结束后提交最终值；最终显示值以服务器 `b.speed` 更新为准，拒绝时恢复到最近确认值。
- 初始/重连值来自现有 `b.start` 当前速度；后续值来自 `b.speed`。客户端按 `phase` 和 `phaseInstance` 校验更新，不重建 Battle。
- 滑条只挂载在战斗 HUD；不创建浏览器偏好、房间大厅字段或额外持久化字段。

## 速度范围与兼容

- 将服务器 `MatchCombatClock.setSpeed()`、客户端 runner 的 `b.speed` 校验、SDK 共用时钟校验及协议/界面测试上限统一改为 `4.0`，继续使用 0.1 步进。
- 保持服务端 FieldRunner、HeadlessPacer、Boss 期限、客户端 runner、恢复及观战共用既有动态时钟；每个速度消费者必须允许 `4.0`，不能出现服务器接受但客户端丢弃的消息。
- 继续使用现有 `b.start` 的阶段速度/计时字段和 `b.speed` 的广播，不新增独立速度广播。
- 只移除本机 `plugins/combat-speed` 插件包及其包内配套文件；不移除已跟踪的 SDK、服务端时钟、协议或其他插件代码。

## 验收条件

1. `0.1`、`2.0`、`4.0` 被接受；低于 `0.1`、高于 `4.0`、非有限值及非 0.1 步进值被拒绝。
2. 房主可在活动战斗阶段调速；非房主、观战者、暂停状态和非战斗阶段均不能改变速度。
3. 当前 Match 的后续战斗阶段沿用设定；新建 Match 使用 `2.0`。不写入跨 Match 偏好。
4. 所有活动字段、客户端/服务端模拟、结果期限、Boss 时钟及观战画面以同一服务器速度前进；过期 `phaseInstance` 更新仍被忽略。
5. HUD 仅在活动战斗阶段显示控制；房主可操作，其他玩家只读；拖动结束后以服务器确认值收敛。
6. 可选插件列表不再包含本机 `combat-speed`；`life-rescue` 和通用 SDK 时钟能力仍可用。

## 验证范围

- Match/时钟回归：权限与阶段门禁、数值边界、跨阶段沿用、新 Match 默认值、暂停/冻结、字段期限重基准与消息广播。
- 客户端 runner 回归：`4.0` 的 `b.speed` 被接受、超过上限及旧阶段实例消息被拒绝。
- HUD 回归：仅活动战斗可见、房主可操作、非房主只读、提交后以服务端值更新。
- 本机插件索引/服务启动回归：删除 speed 插件后仍加载其他插件，检查 `life-rescue` 保持可选。
- 运行受影响的定向测试、项目全量测试及 Vite 构建；使用本机浏览器检查房主/队友界面与实际同步。静态测试或构建不替代浏览器运行验证。
