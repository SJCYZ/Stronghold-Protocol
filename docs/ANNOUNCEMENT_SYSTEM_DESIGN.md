# 网站滚动公告设计稿

## 目标

让维护者通过站内管理界面维护滚动公告，并让公告在游戏站所有页面即时滚动显示。优先复用现有公告配置、校验和 WebSocket 推送，避免引入第二套公告协议。

## 当前实现

- `public/js/main.js` 在应用根节点挂载 `AnnouncementBanner`，标题、主页、房间和对局路由共用公告组件。
- `server/announcements.js` 从 `config/announcements.json`（或 `SP_ANNOUNCEMENTS_FILE` 指定的文件）读取公告；有效配置每两秒轮询，变化后通过 WebSocket 广播。
- `shared/announcements.js` 校验公告并选出当前展示项；同类型同时有效时优先级为紧急、提醒、通知，同级按开始时间排序。
- 目前滚动条是悬浮式窄区域；Studio 是独立页面，不由游戏站应用根节点挂载。
- Studio 写入接口沿用本机/局域网访问限制和 `X-SP-Studio` 密钥；当前没有通用管理员角色或公开的公告编辑接口。

## 已确认范围

- 增加站内公告管理界面。
- 公告显示在游戏站所有页面。
- Studio 管理页沿用局域网访问限制和密钥；不新增公网管理权限。
- 滚动条采用顶部全宽窄条。

## 方案

### 管理入口

在现有 Studio 中增加“网站公告”页面，复用 Studio 的访问限制、密钥验证、页面导航和错误提示。游戏站公开页面只负责展示公告，不显示编辑控件。

首版管理滚动公告，不改造现有弹窗公告。编辑器提供：

- 新建、编辑、启用/停用和删除。
- 公告正文、级别、开始时间、持续秒数。
- 保存前预览；保存成功后显示已发布状态。
- 列表显示启停状态和排期，帮助识别当前及即将生效的公告。

继续使用现有字段和约束：最多 100 条、正文最多 500 字、持续 1 至 86400 秒、级别为通知/提醒/紧急。正在生效的多条公告仍由现有优先级规则选出一条展示。

### 游戏站展示

- 复用 `AnnouncementBanner` 和现有 WebSocket 消息，不增加浏览器轮询或新的公开读取 API。
- 将公告改为页面顶部的全宽窄条，避开安全区并预留正文空间；所有游戏站路由共用同一实例，切换页面不重复挂载。
- 保留紧急/提醒/通知的视觉级别、关闭按钮和按公告版本记忆关闭状态。公告内容或排期变化后按新版本重新显示。
- 保留系统减少动态效果偏好：该偏好开启时公告静态呈现，仍能完整阅读和关闭。
- Studio 管理页不属于游戏站页面范围，首版不显示滚动条。

### 保存与即时生效

- 新增受保护的 Studio API，仅处理滚动公告条目；弹窗公告条目由服务端原样保留。
- API 继续使用共享公告解析器进行完整校验。无效内容、配置文件不可写或配置被停用时拒绝保存，并在管理页说明原因；当前有效配置保持不变。
- 使用配置文件同目录的临时文件完成写入，再原子替换目标文件，避免进程读到半份 JSON。
- 管理页读取配置时取得版本标记；保存时提交该标记。若另一位维护者先保存，返回冲突并要求刷新后再编辑，避免静默覆盖。
- 保存成功后立即让公告服务重新加载并刷新 WebSocket 广播；周期轮询继续保留，用于接收服务器文件系统上的外部修改。

## 权限边界

首版管理页复用 Studio 当前的本机/局域网访问限制和密钥，游戏站公开页面没有写入能力，也不新增 SSO 管理角色。该方案不支持从公网任意地点远程编辑；若需要公网编辑，需另行确定管理员身份与授权方式后再扩展，不放宽整个 Studio 的访问门槛。

## 验收标准

1. Studio 可新增、编辑、停用和删除滚动公告；无效配置不会覆盖当前有效公告。
2. 两位维护者基于同一旧版本编辑时，后提交者收到冲突提示，不覆盖先提交的内容。
3. 保存成功后，已打开的游戏站页面无需刷新即可收到新公告；刷新或重启后排期仍有效。
4. 标题、主页、房间和对局页面只出现一个顶部公告条；页面切换不会重复显示。
5. 用户关闭当前公告后，同一版本不再出现；编辑正文或排期后作为新版本重新显示。
6. Studio 的访问限制和密钥校验保持生效；弹窗公告内容不被滚动公告编辑器改写。

本设计已确认，实施步骤见 `docs/superpowers/plans/2026-10-24-website-announcements.md`。
